# SG Group News Publisher — 導入前の説明

## 何のプラグインか

今回のニュース自動公開向けに作成した、sggroup.jp専用のWordPressプラグインです。名称は **SG Group News Publisher**、バージョンは **0.1.0**。WordPress公式ディレクトリから取得した既製品ではなく、ソースを確認できる独自実装です。

役割は、投稿者ID 5の接続を使い、指定のNewsカテゴリーに日本語・英語の原稿を下書き保存し、保存結果を確認してから公開するための専用APIを提供することです。ニュース収集・記事生成・毎時実行はCodex側が担当します。プラグインの導入だけで監視や公開が始まることはありません。

## なぜ必要か

指定の原稿形式には、記事内に限定した `<style>` と図表があります。通常の投稿者がWordPressの標準投稿APIを使うと、KSESというHTMLフィルターにより必要なstyle要素が削除されます。

このプラグインは、受け取ったHTML・CSSを制限付きの解析器で検証し、検証を通った原稿を専用メタデータに保存して記事表示に使います。通常の `post_content` にはKSESを通した本文を保存します。投稿者に `unfiltered_html` を与える方法や、サイト全体のKSESを無効にする方法は使いません。

## 権限と操作範囲

| 項目 | 実装した範囲 |
| --- | --- |
| 公開用アカウント | 固定の投稿者ID **5**。Codexの接続は投稿者のまま維持 |
| 初期設定 | サイト管理者が自分の管理画面で実行。管理者の接続情報をCodexに渡す必要はない |
| 追加権限 | このユーザーだけに **sgnews_publish** を付与。Authorロール自体は変更しない |
| 対象カテゴリー | **258 / news** のみ |
| 言語 | 既存の `sg-group-language-controller` の **261 / ja、262 / en** のみ |
| 記事の更新対象 | このプラグインが管理し、投稿者ID 5が所有する記事のみ。他の既存記事を一括変更しない |
| 管理者設定画面 | **設定 → SGGroup News Publisher**。管理権限・POST・WordPress nonce・固定ユーザーと依存機能を検証 |

有効化時には専用権限を自動付与しません。管理者が設定画面の **「投稿者ID 5に専用権限のみを付与」** を押したときに付与します。対象アカウントが投稿者だけのロールであることなどの条件が揃わなければ、設定を拒否します。

プラグイン管理記事は、管理者以外の通常編集・削除経路を制限します。投稿者による修正は、内容と履歴を確認する専用API経由になります。管理者による通常編集は可能ですが、保存済み原稿の整合性が変わると専用表示の検証に通らず、通常本文の表示に戻ることがあります。

## 提供するAPI

APIの名前空間は `/wp-json/sgnews-publisher/v1` です。WordPressの既存認証を利用し、公開・下書き操作には投稿者ID 5、専用権限、投稿編集・公開権限を要求します。匿名利用はできません。状態確認だけは、投稿者ID 5またはサイト管理者が利用できます。

| 機能 | 処理 |
| --- | --- |
| 状態確認 | 導入コードのSHA-256、ユーザー、依存機能、権限、処理中の状態を返す |
| 原稿の正規化 | HTML・CSSを検証し、保存する正規形とハッシュを返す。記事は作成しない |
| 処理の占有・更新・解放 | 複数の実行が同じ公開処理を同時に進めることを防ぐ |
| 下書き保存・読み戻し | 日英の検証用下書きを保存し、本文・言語・カテゴリー・SEOを読み戻す |
| 非公開プレビュー | 管理対象の下書きを、実際の有効テーマで描画したHTMLとして返す |
| 公開・修正 | 日英両方の下書きとハッシュを確認し、記事を作成または既存の管理記事を更新する |
| 操作履歴の照合 | 応答が途切れた処理の実行結果を確認し、重複投稿を防ぐ |

日英の公開は別々のWordPress操作です。片方だけ公開された場合に備え、記事IDと履歴を保持して復旧します。二言語を完全に同時公開するトランザクションではありません。原稿の事実確認・翻訳・独立レビュー・画面検証は実行側の検証であり、APIにハッシュを渡すだけで記事品質が証明されるものではありません。

## 保存データとサイトへの影響

専用のデータベーステーブルは作成しません。WordPressの既存の投稿・投稿メタデータ・options・ユーザー権限と、既存AIOSEOの仕組みを使います。

- 記事ごとに、検証済みHTML、原稿のSHA-256、タイトル等の4項目、言語、管理識別子、操作キー、公開先ID、レビュー識別用ハッシュを保存します。専用メタデータ名は `_sgnews_*` です。
- 対象記事を無料公開として保存するため、既存の `_sg_sppp_mode` と `_sg_sppp_sale` は `none`、言語項目は日英の値にします。
- optionsに処理の占有状態・操作履歴・言語別記事IDの対応を保存します。専用の1行に限定した比較更新SQLがあり、汎用SQL実行APIはありません。
- 検証用下書きと操作履歴を自動消去する機能はありません。復旧に使う履歴を不用意に削除すると重複防止に影響します。
- 本文表示・権限判定・AIOSEOスキーマのフィルターを登録します。管理識別子のない通常の記事では元の値を返します。管理記事のArticle系スキーマには無料アクセスの値を設定します。
- SEOのタイトル・説明はAIOSEOの登録済み読取・更新機能を呼び、保存結果を確認します。必要な新規SEO行の作成はAIOSEO自身の内部REST処理に委ねます。

このプラグイン自身には、外部へのHTTP送信、アクセス解析・テレメトリー、ニュース取得、外部JavaScript読込、WordPress cron登録、自動アップデーター、認証情報の入力・保存機能はありません。実行中にWordPress本体・既存テーマ・既存プラグインの通常の処理は呼ばれます。

このPHP本体が設定するSEO項目は記事別タイトル・説明と無料アクセスのスキーマ値です。NewsArticleの種類、記事スキーマが一つだけであること、Organizationとしての著者・発行者、canonicalとhreflangは、既存AIOSEO・テーマ・言語制御の実出力で別途確認します。プラグインを入れればこれらがすべて整う、とは扱いません。

## HTML・CSSの制限

記事固有のID配下に限定したCSS、許可したHTML要素、制限したSVG図形・テキストを扱います。JavaScript、イベント属性、iframe、外部CSS・フォント、CSSの `url()`、任意のHTML、PHP実行を受け付けません。未対応の構文は黙って削除せず、保存前に拒否します。原稿1件は750,000バイト、CSSは65,536バイトなどの上限があります。詳細は `policy.json` とPHPソースで確認できます。

## 依存機能と検証状況

PHP **8.1以上**、DOM/libxml、固定のNewsカテゴリーと言語タクソノミー、AIOSEOの `aioseo-posts/seo-data-get` と `aioseo-posts/seo-data-update` が必要です。設定画面でこれらの可否を表示します。

2026-10-10時点で、管理者初期設定99項目、実際のDOM/CSS解析45項目、WordPressのテスト用代替関数を使う保存・公開・復旧70項目、合計 **214項目**とPHP構文チェックが成功しています。独立したコードレビューも実施しました。これは実サイトへの導入完了やテーマ・AIOSEOの本番適合を証明するものではありません。実サイトは専用APIが404、専用権限も未付与でした。公開用投稿者の接続認証は確認済みです。

ZIPにはPHP本体、導入説明、制限ポリシー、この説明書を収録します。認証情報、原稿、非公開検証記録、監視ランタイム、テストコードは収録しません。ソースとテストは修正PRから確認できます。

## 停止・無効化・削除

新規公開を止めるには、まずCodex側の毎時監視・公開処理を停止します。現在は停止中です。プラグインを無効化すれば専用APIと専用表示フィルターも停止します。

無効化・削除しても、公開済み記事は自動で非公開にはなりません。保存データやユーザーの専用権限も自動削除しません。記事は通常のKSES済み本文として表示され、専用CSSや一部図表の表示が変わります。通常表示を保ったまま撤去する場合は、対象記事を確認して移行してから無効化する必要があります。

無効化すると、管理記事に対する通常編集・削除の制限と、無料アクセスのスキーマ補正も停止します。無効中に通常本文だけを編集しても、保存済みの専用原稿は更新されません。そのまま再有効化すると以前の専用原稿が表示される場合があるため、復帰前に両方の内容を照合します。無効化はデータと表示を完全に元へ戻す処理ではありません。

処理中に停止した場合は、操作履歴と保存内容を照合して復旧します。異常終了時の公開ロックは勝手に解除せず、サイト管理者の確認を必要とします。履歴を含めた完全削除は、復旧の要否を確認してから別途行います。

## 導入後に行うこと

導入と専用権限の付与後も、すぐに毎時公開を開始しません。実際の下書き保存・全文読み戻し・有効テーマでの日英表示・SEO・canonical/hreflang・公開URL・API容量を確認し、検証済みの初回日英記事を公開して両ページを確認してから、毎時監視を有効にします。

接続済みサービスの無料枠は観測時に100回／24時間の移動窓で、現在の新規日英一組は約50〜54回のAPI呼出しに復旧余裕を加えた容量が必要です。これはプラグインの課金や固定の投稿数制限ではありません。実際の利用可能容量を別途確認する必要があります。
